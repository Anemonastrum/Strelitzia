# Strelitzia design

Status: approved by user, with public repository visibility overriding original private proposal. Developer/repository owner verified as Anemonastrum. Implementation plan awaiting execution-method selection.

## Intent and agreed choices
Build an Android kernel manager named Strelitzia, delivered as a GitHub repository with GitHub Actions APK builds. User selected Kotlin, Jetpack Compose, Glasmio, Android 13+ (API 33), and selection of any kernel-supported maximum CPU frequency. Three pages: Home/CPU settings, Device information, Profile/developer. Visual references: https://github.com/NEORUAA/Glasmio and https://github.com/MeiloX/MeiloX. User declined browser mockups.

## Approaches
Chosen: Compose plus Glasmio for actual glass materials and controls, at cost of API 33 minimum and renderer dependencies. Alternative discussed: Compose-only visual approximation, fewer dependencies and broader Android compatibility. User chose Glasmio. MeiloX supplies design inspiration, not copied source or proprietary fonts/assets. Preserve applicable Glasmio notices.

## Scope and UI
- Three labeled bottom navigation destinations with accessible touch targets, scalable text, scrolling content, system light/dark appearance, large headings, rounded grouped surfaces, and Glasmio glass navigation/controls. Avoid continuous decorative animation and background polling.
- Home: explicit root connection action, root/error status, discovered policy cards, related CPUs, current frequency when readable, current minimum and maximum, governor, supported maximum-frequency selector, and explicit Apply action per policy. Frequency display MHz, sysfs writes integer kHz. Missing or inaccessible data displays unavailable, never invented values. Refresh on page entry/resume and explicit refresh, not while backgrounded.
- Quick preset applies policy0=1286000, policy2=1920000, policy5=1920000, policy7=2515000 kHz. Validate all four policies/targets before any write. Disable with explanation when unsupported; never silently substitute frequencies or policy IDs.
- Device: manufacturer/model, Android/API version, kernel version, architecture, SoC when exposed by platform, RAM, and policy/governor information. No privileged identifiers or unnecessary permissions.
- Profile: developer name/handle based on authenticated PAT owner, GitHub profile and repository links opening browser, app version and design/library credits. No GitHub login in app or embedded PAT. Builder-selected default; user may replace developer identity before publication.

## Root and frequency safety
Use explicit user-authorized su commands on background dispatcher, never UI thread. No root prompt at startup; read-only information remains useful without root. Handle missing su, denial, timeout and malformed output. Bound subprocess lifetime and output; cancel/close process resources. Fixed sysfs base /sys/devices/system/cpu/cpufreq; strictly validate policy IDs and integer frequency values, no arbitrary shell command UI or interpolation of unchecked input.
Discover numeric policy directories; read scaling_available_frequencies and current scaling_min_freq/scaling_max_freq. Allow only supported values within readable hardware min/max limits and not below current scaling_min_freq. If supported frequency list or validation bounds are absent/unreadable, show read-only policy with reason; never guess a frequency table. Revalidate before writes. Writes execute inside su shell, equivalent to echo VALUE > .../scaling_max_freq. Never change scaling_min_freq, thermal protection, voltage, governor or permissions as workaround.
Confirmation before writes explains that these are maximum caps, not fixed clocks, and device thermal/power services may override them. Read back scaling_max_freq after each write and report actual value and errors. Preset writes are not atomic: snapshot prior maxima, validate every target first, stop on failure, attempt safe restoration of changed policies and report every restore result; never report transaction guarantees. Unsupported or unsafe restore is reported rather than forced. Allow restoring session-start maximum values through same validation, explicitly labeled session values, not factory defaults. Refresh after operations and block concurrent writes.
No apply-on-boot, background enforcement, services, root scripts installed on disk, or persistent kernel changes. Saved UI selections must never apply automatically.
